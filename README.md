# TC_generator

코딩테스트 문제의 지문·제약·힌트를 넣으면 **정답 코드 확보 → 엣지케이스 테스트케이스 생성 → 오답 코드로 강도 검증 → 문제 정보·그림·테스트케이스를 포함한 문제 가져오기용 zip 내보내기**까지 수행하는 로컬 전용 도구입니다. 백준 문제는 **번호만** 넣으면 됩니다.

요구사항 정의는 [PRD.md](PRD.md)에 있습니다.

## 설치

```bash
pip install -r requirements.txt
```

빌드 단계가 없습니다. npm·번들러·CDN을 쓰지 않으므로 폐쇄망에서도 동작합니다.

## 실행

```bash
python -m tcgen
```

`http://127.0.0.1:8765/`가 브라우저에 열립니다. 외부에 노출되지 않습니다.

| 옵션 | 설명 |
|---|---|
| `--port 8765` | 포트 변경 |
| `--no-browser` | 브라우저를 열지 않음 |
| `--host 127.0.0.1` | 바인딩 주소 (기본값 유지를 권장) |
| `--log-level info` | uvicorn 로그 수준 |

코드를 고친 뒤에는 **서버를 재시작해야 합니다.** 정적 파일은 요청마다 디스크에서 읽히지만 API 라우트는 기동할 때 한 번만 등록되므로, 재시작하지 않으면 새 화면이 뜨면서 새 API만 404가 납니다(그때 404 본문이 재시작하라고 알려 줍니다).

## 필요한 것

| 항목 | 필수 | 없을 때 |
|---|---|---|
| Python 3.11+ | 필수 | — |
| Claude Code CLI (`claude`) 또는 Codex CLI (`codex`) | 선택한 AI에 필요 | 해당 AI로 실행 불가 |
| PyMuPDF 1.x | GPT로 PDF 입력 시 필요 | PDF 페이지 변환 불가 |
| psutil | 권장 | 메모리가 '미측정'으로 표시 |
| Docker 또는 gcc/g++/javac | 선택 | 해당 언어는 SKIP, 격리 없이 실행 |
| 백준 수집본 `boj_problems/` | 선택 | 번호로 불러오기만 503, 나머지 입력 경로는 그대로 |

시작할 때 환경을 점검해 **무엇이 SKIP되는지** 콘솔과 화면 상단에 표시합니다.

## Claude / GPT 구독 선택

화면 상단 **사용할 AI**에서 **Claude Pro 구독** 또는 **GPT (ChatGPT 구독)**을 선택합니다. 선택은 즉시 저장되며 새로고침·서버 재시작 뒤에도 유지됩니다. 모델은 전문가 설정에서 비워 두면 선택한 CLI의 기본 모델을 사용하고, 직접 지정하면 Claude와 GPT별로 따로 저장합니다. AI 전환 시 다른 제공자의 모델 이름이 넘어가지 않습니다.

- Claude: `claude auth login`으로 구독 계정에 로그인합니다. 구독과 소속 조직의 Claude Code 접근 허용이 필요합니다.
- GPT: `codex login`의 **Sign in with ChatGPT**로 로그인합니다. 이 앱은 저장된 ChatGPT 로그인을 사용하며 API 키 로그인 상태에서는 실행하지 않습니다. OpenAI/Codex API 키 환경변수도 GPT 자식 프로세스에 전달하지 않습니다.

[OpenAI 공식 인증 문서](https://learn.chatgpt.com/docs/auth)에 설명된 구독 로그인 경로를 사용합니다. [비대화형 CLI](https://learn.chatgpt.com/docs/non-interactive-mode)로 요청하며 구독의 Codex 사용 가능 범위·한도가 적용됩니다. 계정에 해당 기능이 없는 경우 실제 요청의 오류를 표시합니다. IDE에 포함된 Codex CLI도 찾아 사용하므로 터미널 PATH와 IDE PATH가 달라도 동작합니다.

**로그인 확인**은 선택한 제공자의 상태를 보여 줍니다. 정답·브루트포스·validator·생성기·오답·난이도 평가·그림/PDF 해석에 모두 선택한 AI를 사용합니다. GPT 경로는 AVIF 등 그림을 PNG로 직접 첨부하고 PDF는 페이지별 그림으로 변환합니다(합계 최대 20장). PDF 렌더러는 별도 프로세스에서 실행해 이미지 코덱과 네이티브 라이브러리가 충돌해도 서버가 종료되지 않도록 합니다.

진행 중인 작업과 일괄 실행은 **시작할 때 선택한 제공자·모델을 유지**합니다. 실행 중 선택을 바꾸면 다음에 새로 시작하는 작업에 적용합니다. 일괄 상태와 작업 리포트, 호출 로그에도 제공자를 기록합니다. Codex 요청은 빈 임시 폴더·읽기 전용 sandbox에서 사용자 설정·명령 도구·플러그인·MCP 없이 실행하며, 생성된 코드의 파일 저장과 실행은 기존 엔진이 담당합니다.

## 사용 흐름

**위저드 모드** — 순서대로 실행하며 결과를 확인합니다.

1. **문제 선택·입력** — 사이드바의 검색창 하나로 번호·제목을 검색하고, 백준 DB 문제 목록을 10개씩 탐색합니다. 목록의 문제를 누르면 지문·입출력·제약·예제 프리뷰가 열리며, 확인 후 작업을 시작합니다. 이전 작업은 접힌 '불러온 문제 · 내보내기 기록'에서 다시 엽니다. 비어 있는 항목은 직접 채웁니다.
2. **정답 코드 확정** — 직접 입력하거나 AI가 생성합니다. 작은 입력 생성기 → validator → 독립적인 브루트포스와 대조를 반복합니다. 반례는 `reports/counterexamples.jsonl`에 저장하고 정답 후보만 수정합니다. 브루트포스 실행 실패를 정답 후보의 반례로 사용하지 않습니다.
3. **테스트케이스 생성** — 예제·직접 작성한 경계 입력과 `random`·`scale`·`anti` 유형별 여러 생성기를 사용합니다. 중복 제거·입력 검증·정답 실행을 통과한 **최소 15개**가 목표입니다. 경계 입력은 약 25%, 나머지는 세 유형에 균등하게 나누고, 유형 안에서는 생성기를 번갈아 실행합니다. 탈락분은 새 시드로 제한된 횟수만 보충합니다. 고유 입력이 부족하면 이유를 표시하고 내보내기를 막습니다.
4. **강도 검증** — WA 4개 이상, TLE 1개, MLE 1개를 준비합니다. 문제에 해당하는 경계·범위·초기화·동률·순서·상태·알고리즘·계산·문제별 규칙 결함을 구분하고 코드마다 결함 하나를 요청합니다. 생존 코드마다 직접 입력 또는 대규모 생성기를 요청한 뒤 **동일한 오답 코드들**을 재검사합니다. 기본 보강은 2회(상한 3회)이며, 새 입력이나 추가 kill이 없으면 종료합니다. 생존 코드와 kill rate를 남기고, 100%가 아니어도 다음 단계로 진행합니다.
5. **최종 검증** — 모든 `.in`을 validator로 재검사하고, 확정된 정답 코드를 다시 실행하여 저장된 `.out`과 비교합니다. 이어서 브루트포스 출력도 대조합니다. 브루트포스에만 입력당 500ms·512MB, 전체 약 30초 예산을 적용하며, 예산이 소진되어도 나머지 케이스의 입력·정답 출력 재검증은 수행합니다. 브루트포스의 시간·메모리 초과와 예산 소진은 **미검증**, 입력 제약 위반·정답 코드 재실행 실패·출력 불일치·브루트포스 실행 오류는 **실패**로 기록합니다. 실패가 있으면 내보내기를 막고, 미검증만 있으면 범위를 리포트에 명시하고 진행합니다.
6. **문제 내보내기** — 최종 대조 후 난이도·영역·태그와 작은 예제를 준비하고, 문제 JSON·그림·전체 테스트케이스를 zip으로 묶어 다시 검사합니다. 내보내기 정보 생성·확인으로 평가 근거와 예제를 먼저 볼 수도 있습니다.

실수 출력은 지문의 **출력 설명에 명시된 절대/상대 허용 오차**를 읽어 예제·스트레스·강도·최종 브루트포스 대조에 적용합니다. 예를 들어 `절대/상대 오차 10^-6`이면 `13.341664064126334`와 `13.341664064126`은 같은 답입니다. 오차 선언이 없는 문제는 기존 엄격 비교를 유지하며, 정수 토큰의 다른 값·토큰 누락·NaN/무한대는 실수 비교에서도 통과시키지 않습니다. `.out` 파일과 정답 재실행 결과의 재현성·해시는 계속 엄격하게 검사하고 실제 출력값을 바꾸지 않습니다. 적용한 기준은 실행 로그와 리포트에 남습니다. 현재 `spj=null` 내보내기는 대상 서버의 문자열 채점을 바꾸지 않으므로, 실수 문제에는 대상 채점기에서도 실수 비교 설정 또는 SPJ가 필요하다는 경고를 표시합니다.

**전문가 모드** — `전체 실행`으로 2~6단계를 이어서 실행합니다. 직접 입력한 정답 코드도 사용합니다. 지문 해석 확인 단계는 삭제되었습니다. 두 구현의 일치와 kill rate는 정답의 수학적 증명이 아닙니다.

### 문제 기록과 일괄 실행

문제 목록의 체크박스로 **최대 30개**를 선택하고 **선택 문제 순차 실행**을 누르면 선택 순서대로 정답 확정 → 케이스 생성 → 강도 검증 → 최종 검증 → zip 내보내기를 실행합니다. 페이지 이동·검색 후에도 선택이 유지됩니다. 기존 미완료 작업이 있으면 그 작업을 사용하고, 확정된 정답과 보조 코드가 모두 있으면 정답 생성은 재사용합니다. 그림이 필요하면 설정한 Drive 폴더에서 가져옵니다. 지문·입출력 설명 등 필수 정보가 없으면 해당 문제를 실패로 기록하고 다음 문제로 넘어갑니다.

검증된 zip을 만든 문제에는 자동으로 **✓ 내보내기 완료**와 완료 시각을 표시합니다. 각 문제 오른쪽 **완료** 체크박스로 사용자가 언제든 체크·해제할 수 있습니다. 완료 표시만 바꾸며 기존 zip과 실제 검증 기록은 보존합니다. 수동 조정은 서버 재시작 후에도 유지되고 일괄 실행의 완료 문제 건너뛰기에 반영됩니다. 이후 새 내보내기에 성공하면 다시 자동 완료가 됩니다. 이전 작업의 내보내기 기록도 자동으로 읽어 옵니다. 작업 목록에서 문제를 다시 열거나, 일괄 실행 결과에서 zip을 다운로드할 수 있습니다. **완료 표시된 문제 건너뛰기**는 기본으로 켜져 있으며, 끄고 재실행하면 기존 완료 파일을 보존하는 새 작업을 만듭니다. 자동 완료는 zip 검증 성공을 뜻하며, 수동 완료는 사용자가 지정한 상태로 따로 표시합니다. 일괄 실행 결과의 **완료 문제 묶음 내려받기**로 여러 문제를 하나의 문제 zip에 넣을 수 있습니다.

일괄 실행 도중 실패해도 나머지는 계속 진행합니다. **일괄 실행 중단**은 현재 작업에 중단을 요청하고 대기 문제를 취소합니다. 실행 결과에는 실패 이유가 남고, **미완료 문제 다시 선택**으로 실패·중단 문제를 다시 실행할 수 있습니다. 브라우저 새로고침 중에도 서버 작업은 계속되며, 서버 자체를 종료했다면 재시작 시 미완료 항목을 중단 상태로 복원합니다.

기록과 마지막 실행 상태는 `workspaces/.tcgen-history.json`, `workspaces/.tcgen-batch.json`에 저장합니다. 첫 문제 목록은 기록 전체를 재탐색하지 않고 표시 중인 10개에 대한 저장된 기록만 조회합니다.

### 그림 첨부와 Google Drive

AVIF·PNG·JPEG·GIF·WebP·BMP 그림을 장당 16MB까지 첨부할 수 있습니다. 기존 그림 번호에 파일을 교체하거나 새 그림을 추가하세요. 그림은 PNG로 변환하고, AI가 읽은 전사는 폼에서 확인·수정할 수 있습니다. 정답 확정 시 필요한 그림의 전사가 비어 있으면 자동으로 그림을 읽습니다. 파일도 전사도 없는 필수 그림이 있으면 정답 확정을 시작하지 않습니다.

전문가 탭의 **이미지 공유 폴더(Drive)** 에 공유 폴더 링크를 저장하면, 백준 문제 **프리뷰를 열 때 해당 문제 폴더의 그림만** 비동기로 받아 보여줍니다. 지문은 먼저 표시하고 그림의 다운로드 중·완료·실패 상태를 따로 표시합니다. 받은 그림은 `.tcgen-cache/figure-previews/`에 보관하며, **이 문제로 작업 시작**을 누르면 완료된 그림을 작업공간에 복사해 재사용합니다. 프리뷰를 거치지 않고 문제를 가져와도 그림을 자동으로 받습니다. 기존 작업에서는 **Drive에서 그림 가져오기**를 누릅니다.

`boj_problems/images/` 검사는 로컬 수집본의 파일 유무만 확인합니다. Drive를 사용하는 화면에서는 이 로컬 누락 경고를 다운로드 실패로 표시하지 않으며, 실제 다운로드 오류를 그림 상태에 표시합니다.

```text
공유 폴더/
  1002/1.avif
  1004/1.avif
  1004/2.avif
```

`공유 폴더/images/문제번호/순번.avif` 구조도 지원합니다. **링크가 있는 모든 사용자에게 보기 허용**된 폴더는 API 키 없이 사용할 수 있습니다. 폴더 목록은 10분간 메모리에 캐시하고, 이미 작업공간에 있는 그림은 다시 다운로드하지 않습니다. 그림 수와 `1..N` 번호가 지문과 일치해야 연결합니다. 전체 이미지 묶음을 내려받거나 압축을 풀지 않습니다. 공개 Drive 페이지 구조·다운로드 제한이 바뀌면 수동 첨부 또는 공식 API 경로를 사용할 수 있습니다.

비공개 폴더에는 접근 권한이 있는 OAuth 액세스 토큰을 `TCGEN_DRIVE_ACCESS_TOKEN`으로 지정합니다. 공개 폴더를 공식 API로 조회하려면 Drive API를 활성화한 `TCGEN_DRIVE_API_KEY`도 사용할 수 있습니다. 토큰이 만료되면 갱신이 필요합니다. 키·토큰은 브라우저나 설정 파일에 저장하지 않습니다. 공유 링크·모델은 저장소에서 제외된 `.tcgen-settings.json`에 저장됩니다. `TCGEN_DRIVE_FOLDER` 환경변수로 폴더를 지정할 수도 있습니다. 이 로컬 앱 연동은 채팅의 Google Drive 플러그인 연결과 별개로 동작합니다.

## 설계상 중요한 사항

### 안전장치

- **정답 코드가 확정되기 전에는 케이스 생성과 내보내기가 차단됩니다.** 틀린 테스트가 OJ에 올라가는 것을 구조적으로 막습니다.
- **기대 출력은 추측하지 않습니다.** 확정된 정답 코드를 실행해서 얻습니다.
- **모든 생성 입력은 validator를 통과해야 채택됩니다.**
- **LLM이 만든 코드도 신뢰하지 않습니다.** 위험 패턴(`subprocess`, `socket`, `os.system` 등)을 정적 스캔해 걸리면 **파일로 쓰지도 않고** 멈춥니다. 디스크에 남지 않으므로 나중에 실수로 실행될 여지도 없습니다.

### 백준 문제 불러오기

첫 화면은 DB에서 11개만 읽어 문제 10개를 **HTML에 바로 포함**합니다. 별도 목록 API, 전체 개수 집계, 환경 점검, 작업 화면 초기화를 기다리지 않고 목록을 표시합니다. HTML과 JS가 엇갈려 초기화가 실패하지 않도록 자산 URL에도 버전을 붙입니다.

이후 검색·페이징·전체 개수는 번호·제목·제한만 담은 작은 메타데이터 캐시(`.tcgen-cache/catalog/`)에서 조회합니다. 최초 실행이나 수집본 변경 시 한 번 생성하고, 서버를 재시작해도 재사용합니다. DB와 WAL의 변경을 감지하면 자동으로 갱신하며 원본 DB는 수정하지 않습니다. 브라우저는 다음 10개만 미리 받아오고, 이전 작업 목록은 펼칠 때 불러옵니다.

사이드바에서 번호·제목을 검색하고 문제 프리뷰의 **이 문제로 작업 시작**을 누르면 지문·입력·출력·제약·힌트·예제·시간/메모리 제한이 한 번에 채워집니다. 지문은 로컬 수집본(`boj_problems/`)에서 읽으며 **LLM 파싱 단계가 없습니다**.

| 항목 | 위치 |
|---|---|
| 수집본 DB | `boj_problems/boj_problems.db` (읽기 전용으로만 엽니다) |
| 그림 파일 | `boj_problems/images/<번호>/<순번>.<확장자>` |
| 경로 변경 | 환경변수 `TCGEN_BOJ_DIR` |

수집본이 없으면 이 기능만 503으로 거절되고 나머지 입력 경로는 그대로 동작합니다. 수집본은 1.9GB 외부 자산이라 저장소에 넣지 않습니다(`.gitignore`).

읽어 오면서 **자동으로 채우지 못한 것은 전부 로그에 남깁니다.** 조용히 넘어가면 사람은 다 채워진 줄 압니다.

- 시간 제한이 `서브태스크 참고`처럼 숫자가 아닌 경우 → 기본값으로 가정했다고 표시
- 문제 설명·입력 설명·출력 설명이 비는 경우 → **각각** 직접 채우라고 표시
- 그림 파일이 개수 또는 번호(`1..N`)로 지문의 그림과 어긋나는 경우 → 위치 대응을 **생략**하고 표시
- 섹션이 비정상적으로 크거나 필드가 상한을 넘는 경우 → 건너뛰거나 자른 사실을 표시

그림은 등장 순서로 파일과 짝지어집니다. 그래서 **개수와 번호가 모두 맞을 때만** 연결하고, 하나라도 어긋나면 연결하지 않습니다 — 한 칸 밀린 그림은 비어 있는 그림보다 나쁩니다.

저장된 `body_text`는 쓰지 않고 원본 HTML을 직접 옮깁니다. `body_text`에서는 `2^31`이 `2 31`로, 표의 행·열이 한 줄로 뭉개져 **제약 조건이 조용히 바뀝니다**(수집본의 8,386개 섹션이 위첨자를, 3,394개가 표를 담고 있습니다). 위첨자는 `^`, 아래첨자는 `_`, 표는 `A | B | C`로 행·열을 유지하고, `<pre>` 안의 들여쓰기는 그대로 둡니다 — 아스키 격자와 미로가 거기 있습니다.

문제를 선택하고 비어 있는 항목·그림 전사를 채운 뒤 전문가 모드의 `전체 실행`으로 이어갈 수 있습니다. 같은 번호를 다시 불러오면 `boj-1000-2`처럼 새 폴더가 생기고 기존 작업은 덮이지 않습니다.

### PDF 지문 입력(선택)

그림은 붙여넣기로 옮겨지지 않습니다. 더 나쁜 것은 **그 사실이 어디에도 드러나지 않는다**는 점입니다. 파서는 경고 없이 성공하고, 정답 코드·브루트포스·검증기·생성기가 전부 그림에 있던 제약을 모른 채 만들어집니다. 좌표계나 규칙을 그림이 정의하는 경우에는 정답과 브루트포스가 같은 오해를 공유해 예제까지 맞추므로, 스트레스 대조마저 통과해 버립니다.

그림 파일을 따로 첨부하는 대신 **지문 PDF를 그대로 올릴 수도 있습니다.** CLI가 PDF를 직접 읽어 항목을 채우고, 그림마다 역할을 분류해 내용을 글로 옮깁니다.

| 역할 | 뜻 | 전사가 비면 |
|---|---|---|
| `spec` | 입력 형식·좌표계·격자 구조를 그림이 정의 | **경고** — 풀이가 성립하지 않음 |
| `rule` | 연산·이동·판정 규칙 자체를 그림이 정의 | **경고** — 풀이가 성립하지 않음 |
| `example_visual` | 예제를 그림으로 보여줄 뿐 본문과 겹침 | 무방 |
| `decorative` | 단순 삽화 | 무방 |

전사는 초안입니다. 위저드 1단계의 **그림** 칸에서 직접 고칠 수 있고, 고치면 기존 정답 확정은 무효가 됩니다. 전사가 비어 있는 그림도 프롬프트에 `전사 없음`으로 **명시해서** 싣습니다 — 그림의 존재를 숨기면 LLM이 지문을 완전한 것으로 착각하고 빈칸을 상상으로 메우기 때문입니다.

백준에서 불러온 문제의 그림은 `assets/figures/figure-N.*`로 복사되고, 지문 본문에는 `[그림 N]` 표시가 그 자리에 남습니다. 역할은 **`spec`으로 시작합니다** — 전사 없는 그림을 `decorative`로 두면 그림이 정한 규칙이 조용히 사라지기 때문입니다. 단순 삽화라면 위저드 1단계에서 역할을 내리세요.

PDF 읽기는 `--add-dir`로 작업공간 `assets` 폴더만 열고 `Read`만 허용하는 단일 호출로 처리합니다. 쓰기·실행·네트워크 도구는 다른 호출과 똑같이 차단된 채입니다. 업로드된 파일명은 쓰지 않고 `assets/statement.pdf`로 고정 저장합니다.

### 격리

Docker 실행기가 붙기 전까지는 **격리 없이 로컬에서 실행**됩니다. 화면 상단에 배너로 계속 표시되며, 리포트에도 기록됩니다. 타임아웃 시 프로세스 트리를 전부 종료하고, 출력 상한을 적용하며, 환경변수를 최소화합니다.

Windows에서 메모리는 psutil 폴링(약 15ms 간격)으로 재므로 **MLE 판정은 참고치**입니다. 리포트에 측정 방식이 항상 적힙니다.

### 문제 zip 형식

첨부한 문제 묶음 형식처럼 폴더별로 문제를 넣습니다. 개별 내보내기는 `1/` 하나, 일괄 묶음은 `1/`, `2/`, …로 연속 번호를 사용합니다.

```text
1/
  problem.json
  testcase/
    1.in
    1.out
    2.in
    2.out
    …
```

`display_id`는 백준 번호, `time_limit`는 ms, `memory_limit`는 MB입니다. 본문·입력·출력·힌트는 `{format: "html", value: "…"}`로 넣습니다. 출처는 **Baekjoon Online Judge**, `template={}`, `spj=null`, `rule_type="ACM"`, `answers=[]`로 고정합니다. `test_case_score`에는 실제 입력·출력 파일 이름을 1부터 연속으로 넣고 ACM 형식에 맞춰 각 `score`를 100으로 둡니다. zip을 다시 읽어 JSON 필드·파일 대응·번호·줄바꿈·CRC를 확인합니다.

본문의 `[그림 1]` 같은 자리에 PNG data URI를 내장합니다. 원래 그림 위치가 유지되고 별도 로컬 이미지 경로나 외부 이미지 서버가 필요하지 않습니다. 원하는 위치로 표시를 옮길 수 있으며, 위치 표시 없이 첨부한 그림은 본문 뒤에 넣습니다. 그림 파일이 누락되면 내보내기를 막습니다. HTML로 보낼 때 원문은 이스케이프하고 줄바꿈·들여쓰기를 보존합니다.

예제는 최종 입력·출력 검증을 통과한 케이스 중 **읽기 쉬운 작은 입력 2~4개(기본 3개)**를 고릅니다. 원문 예제를 우선하면서 유형·출력이 다른 사례를 섞고, 큰 scale 입력은 제외합니다. 2개 미만이면 작은 입력 생성기로 보충하며 validator·정답 실행·가능한 범위의 브루트포스 대조를 거칩니다. 서로 다른 작은 예제를 1개만 확보하면 사유를 남깁니다. 예제 출력은 AI가 추정하지 않습니다.

기존 테스트케이스 전용 `exporter.export_zip` 유틸리티와 과거 zip 다운로드는 호환용으로 유지합니다. 화면·일괄 실행에서 새로 내보내는 기본 형식은 위의 **문제 zip**입니다.

### 난이도·문제 영역·태그

난이도 이름은 code-place의 백엔드 `utils/constants.py`와 프런트엔드 `utils/constants.js`에 정의된 **VeryLow / Low / Mid / High / VeryHigh** 5단계를 따릅니다. 백엔드 문제 가져오기의 `utils/shortcuts.py:get_difficulty`도 이 다섯 값을 처리합니다. 이 저장소에서 확인한 것은 난이도 이름과 가져오기 처리이며, 아래 점수 구간은 **생성기가 자체적으로 정한 내부 기준**입니다.

LLM이 지문·입력 범위·확정된 정답 코드를 읽고 다음 항목을 각각 정수 0~4점으로 평가하며 근거를 작성합니다. 해당하는 가장 낮은 점수를 선택하도록 요청합니다.

| 항목 | 0~1점 | 2점 | 3~4점 |
|---|---|---|---|
| 필요 지식 | 입출력·사칙연산·반복·배열·정렬 | 스택·큐·기본 그래프 탐색·기초 DP | 복잡한 DP·알고리즘 조합·고급 자료구조·플로우 |
| 발상·모델링 | 지문을 그대로 구현·단일 표준 패턴 | 조건 분해·상태 모델링 | 비자명한 불변식·환원·고급 증명 |
| 구현 복잡도 | 직접 계산·단순 반복·컨테이너 | 격자·그래프·여러 상태·기본 DP | 복잡한 상태 전이·자료구조 상호작용 |
| 효율화 난도 | 명백한 선형 풀이·단순 완전 탐색 | 입력 범위에 맞는 시간복잡도 선택 | 가지치기·차원 축소·고급 최적화 |

앱이 합계 0~16점을 계산해 등급으로 변환합니다. LLM이 등급 이름을 임의로 정하는 방식은 아닙니다.

| 합계 | 내보내는 값 | 표시 의미 |
|---|---|---|
| 0~2 | VeryLow | 매우 쉬움 |
| 3~5 | Low | 쉬움 |
| 6~9 | Mid | 보통 |
| 10~12 | High | 어려움 |
| 13~16 | VeryHigh | 매우 어려움 |

고정 기준 예시는 A+B=(0,0,0,0) → VeryLow, 배열 최댓값=(1,0,1,0) → VeryLow, 단순 정렬=(1,1,1,1) → Low, 격자 BFS 최단거리=(2,1,2,2) → Mid, 세그먼트 트리와 비자명한 환원=(4,3,3,3) → VeryHigh입니다. 점수 구간은 `tcgen/config.py`, 항목별 상세 기준과 기준 예시는 `tcgen/engine/metadata.py`에 있습니다. 기준 버전은 **tcgen-difficulty-v2**이며, 이전 3단계 평가 캐시는 다음 정보 생성 시 새 기준으로 재평가합니다. 이미 내려받은 zip은 자동으로 수정하지 않습니다.

테스트 수, 코드 길이, kill rate로 난이도를 정하지 않습니다. 백준/solved.ac 등급과 직접 대응하지 않으며 실제 사용자 풀이 시간·정답률로 보정한 통계적 난이도도 아닙니다. 합계와 등급 변환은 고정되어 있지만 각 항목의 첫 평가는 LLM 판단이므로 평가 근거를 확인할 수 있게 제공합니다.

같은 문제 내용·같은 정답·같은 기준의 평가는 저장해 작업폴더나 서버가 바뀌어도 재사용합니다. 정답 코드의 주석·공백만 바뀐 경우에도 같은 평가를 사용합니다. 기준 또는 풀이가 바뀌면 새로 평가하고, 항목별 근거는 내보내기 화면과 리포트에 남깁니다. 공통 캐시는 `workspaces/.tcgen-classifications/`, 작업별 평가는 `reports/classification.json`에 있습니다.

영역은 LLM이 **0 구현 / 1 수학 / 2 자료구조 / 3 탐색 / 4 정렬 / 5 알고리즘**에서 하나를 고르며 해당 영역이 없으면 구현으로 처리합니다. 태그는 정해진 기존 어휘 안에서 핵심 알고리즘 **최대 3개**를 고릅니다. DFS/BFS/DP 등 동의어는 각각 깊이 우선 탐색/너비 우선 탐색/동적 계획법으로 통일하고, 임의의 새 태그·범위 밖 점수는 재요청하거나 실패로 처리합니다.

## 작업 폴더

`workspaces/<문제slug>/` 하나가 문제 하나입니다. DB가 없으므로 폴더를 복사하면 그대로 이식됩니다.

```
problem.json          문제 정보(그림 전사 포함)
assets/               statement.pdf — 올린 지문 PDF
assets/figures/       figure-N.* — 지문 속 그림, 본문의 [그림 N]과 대응
solutions/            sol.py, brute.py
validator.py          입력 검증기
gens/                 생성기 스크립트(시드 기록)
cases/                1.in, 1.out, …, index.json
mutants/              wa_*.py, tle_*.py, mle_*.py
reports/              report.md, run.json, classification.json
export/               <slug>_problem.zip
logs/                 LLM 호출 기록
```

## 개발

```bash
python -m pytest                 # 전체 테스트
python -m pytest -m "not slow"   # 빠른 테스트만
python -m pytest --cov=tcgen --cov-report=term-missing
```

테스트는 가짜 LLM을 쓰지만 실행·비교·패키징은 진짜로 돌립니다. 백준 관련 테스트는 스키마만 같은 작은 DB를 만들어 쓰므로 수집본 없이도 돌아가고, 실제 수집본을 대상으로 하는 연기 테스트(`-m integration`)만 수집본이 없으면 건너뜁니다. 단위 테스트가 모두 통과하는 상태에서도 실제 지문에서 깨지는 경우가 있어 둔 것입니다.

### 구조

| 모듈 | 역할 |
|---|---|
| `tcgen/compare.py` | OJ와 동일한 출력 비교 규칙 (가장 중요) |
| `tcgen/exporter.py` | 케이스 파일·기존 테스트케이스 전용 zip |
| `tcgen/problem_export.py` | 문제 JSON·그림·케이스 패키징과 묶음 zip 검증 |
| `tcgen/engine/metadata.py` | 난이도 기준·영역·태그 분류와 작은 예제 선정 |
| `tcgen/runner/` | 실행기 어댑터 (`local` → 향후 `docker`/`wsl`) |
| `tcgen/safety.py` | 실행 전 정적 위험 패턴 스캔 |
| `tcgen/llm.py` | Claude CLI headless 호출 (도구 권한 차단) |
| `tcgen/boj.py` | 백준 수집본 로더 + 지문 HTML→텍스트 변환 (읽기 전용) |
| `tcgen/engine/` | 정답 확정·케이스 생성·강도 검증·오케스트레이션 |
| `tcgen/server.py` | 로컬 HTTP API + SSE |
| `tcgen/static/` | 브라우저 UI (의존성 없음) |

### 확장 지점

- **다른 언어 추가** — `tcgen/runner/base.py`의 `Runner` 프로토콜을 구현하고 `LANGUAGE_REQUIREMENTS`에 등록
- **Docker 격리** — `DockerRunner`를 만들어 `isolated = True`로 두면 배너가 자동으로 사라짐
- **문서 업로드** — 텍스트 추출기를 붙여 `parse_statement`에 넘기면 됨
